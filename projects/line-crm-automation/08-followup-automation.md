# 08｜Follow-up Automation

## 1. 設計原則

完成診斷但沒有預約的人，佔比大約 70%。這群人不是沒興趣，是還沒到時候。

追蹤訊息的目的**不是催預約**，是讓他在三次接觸之後，覺得知育懂他的問題。

三條硬規則：

1. **每一則都要帶他自己的診斷內容。** 泛用內容會被當廣告。
2. **前兩則不放 CTA。** 第三則才問。
3. **只發三次。** 第七天之後沒反應就停，改成每月電子報。連續推播是封鎖率最高的行為。

---

## 2. 排程時機

| 步驟 | 發送時間 | 內容型態 | 有 CTA |
|---|---|---|---|
| D1 | 診斷完成後 24 小時（校正到當地 10:00–20:00） | Insight 延伸 | 無 |
| D3 | 診斷完成後 72 小時 | 對應產業案例（Flex） | 弱 CTA |
| D7 | 診斷完成後 7 天 | 直接邀約 30 分鐘 | 強 CTA |
| ABANDON_24H | 診斷中斷 24 小時 | 提醒續測 | 續測 |

**時段校正很重要。** 診斷完成時間可能是凌晨 2 點，24 小時後就是凌晨 2 點發推播。排程時計算：若落在 20:00–10:00 之間，一律順延到隔天 10:00。

---

## 3. 取消條件

發送前檢查，任一成立就取消該則並記錄 `cancel_reason`：

| 條件 | reason |
|---|---|
| `users.current_state = 'HANDOFF'` | `handed_off` |
| `users.do_not_contact = true` | `opted_out` |
| `users.is_blocked = true` | `unfollowed` |
| 已建立 `leads` 且 `contact_status != 'NEW'` | `already_contacted` |
| 使用者在上一則 Follow-up 之後有任何互動 | `user_engaged`（改為人工判斷） |

## 4. 文案

### 4.1 Day 1｜Insight 延伸

不重複診斷內容，往前推一層，講「第一步該做什麼」。

**通用結構**

```
{{name_or_empty}}昨天的診斷裡，你提到 {{blocker_label}} 是目前最卡的地方。

{{insight_extension}}

{{first_action}}
```

**依 Segment 的 `insight_extension` 與 `first_action`**

| Segment | insight_extension | first_action |
|---|---|---|
| GM | 這一類問題，八成不是投放技術的問題，是產出節奏的問題。廣告要穩，前提是素材要能穩定供應。 | 這週可以先做一件事：把過去三個月成效最好的三支素材找出來，看它們有什麼共同點。 |
| AX | 大部分公司在這個階段會直接去比較工具。但工具選錯的成本，遠低於流程沒盤點的成本。 | 這週可以先做一件事：挑一件你每週都要做三次以上的工作，把它的步驟寫下來。寫得出來的，才自動化得了。 |
| PO | 重複工作最貴的地方不是時間，是它讓人沒有餘裕思考。 | 這週可以先做一件事：記錄一週，看那件事實際花掉多少小時。多數老闆估的數字都低於實際的一半。 |
| CT | 員工不會用 AI，通常不是學習能力的問題，是沒有人告訴他「在你的工作裡，哪一段可以用」。 | 這週可以先做一件事：問三個同仁，他們每天最不想做的工作是什麼。那就是訓練的起點。 |
| BC | 策略卡住的時候，多數人會去找新方法。但通常問題出在舊的決策沒有被結束。 | 這週可以先做一件事：列出三件你知道該停但一直沒停的事。 |

**不放連結、不放按鈕。** 這則的價值就在於它沒有要你做任何事。

### 4.2 Day 3｜案例

用 Flex（`flex/followup-day3-case.json`），依 `primary_service` 與產業挑一則。

**案例庫至少準備 8 則**，每則要有：產業、原始問題、做了什麼、兩個數字、一句話總結。

| 對應 | 案例主題（依知育既有客戶調整） |
|---|---|
| `marketing` × 食品 | 食品品牌把廣告素材產製流程固定下來後的成效變化 |
| `marketing` × 零售 | 電商從投放優化轉成轉換路徑優化 |
| `ai` × 製造 | 傳產把報價與規格查詢做成內部知識庫 |
| `ai` × 服務 | 服務業把客服常見問題做成自動回覆分流 |
| `automation` × B2B | B2B 把每週報表從人工整理改成自動產出 |
| `training` × 全體 | 30 人團隊的 AI 導入內訓，三個月後的實際使用率 |
| `consulting` × 轉型 | 二代接班的傳統產業數位轉型第一年 |
| `consulting` × 成長 | 成長期公司的部門分工與制度建立 |

**訊息前綴**

```
你的狀況跟這一間有點像。

他們一開始遇到的也是 {{blocker_label}}。
```

**Flex 上的按鈕文字用「我想聊聊我的狀況」，不要用「立即預約」。** 差別在於前者是延續對話，後者是業務動作。

### 4.3 Day 7｜邀約

```
{{name_or_empty}}上週幫你做的診斷，結論是{{tier_label}}。

我不確定你現在是不是適合的時間點，所以直接問：

要不要用 30 分鐘，一起看看 {{priority_1}} 這件事，實際上該從哪裡開始？

線上就可以，不用準備資料。談完沒有要合作也沒關係。
```

Quick Reply：

| Label | Value |
|---|---|
| 好，約時間 | `type=cta&v=consult` |
| 這個月不方便 | `type=cta&v=later_month` |
| 暫時不用 | `type=cta&v=stop` |

選「這個月不方便」→ 30 天後再發一次 D7；選「暫時不用」→ 標記 `NURTURE_PAUSED`，只留每月電子報。

**「談完沒有要合作也沒關係」這句不要拿掉。** 它是這則訊息轉換率最高的一句。

### 4.4 ABANDON_24H｜中斷提醒

```
你上次的診斷做到第 {{answered_count}} 題。

剩下 {{remaining_count}} 題，大概 20 秒就有結果。
```

用 `flex/resume-session.json`。只發一次。48 小時後仍未完成就標記 `ABANDONED`，不再打擾。

---

## 5. 第七天之後

| 狀態 | 處理 |
|---|---|
| D7 有回應且選 consult | 進入 Lead Qualification |
| D7 選「這個月不方便」 | 30 天後再觸發一次 D7，最多兩次 |
| D7 無回應 | 標記 `NURTURE_COLD`，停止 Push，改為每月一次電子報（Email 或 LINE 群發） |
| 任何時候主動回訊息 | 立刻通知 Slack，取消所有排程，轉人工 |

每月電子報用 LINE 的「群發訊息」功能，不走 Push API，成本較低。內容是知育的月度洞察，不針對個人。

---

## 6. 成效追蹤指標

| 指標 | 計算 | 目標 |
|---|---|---|
| 診斷完成率 | COMPLETED / 加好友數 | > 55% |
| 診斷 → Lead 轉換率 | leads / COMPLETED | > 25% |
| D1 回應率 | D1 後 48 小時內有互動 | > 8% |
| D3 點擊率 | 案例 Flex 按鈕點擊 | > 12% |
| D7 預約率 | D7 選 consult | > 10% |
| 整體加好友 → HOT LEAD | HOT / 加好友數 | > 5% |
| 封鎖率 | unfollow / 加好友數 | < 8% |

**封鎖率超過 8% 就要砍訊息數量，不是改文案。** 這條線比任何轉換率都重要。
