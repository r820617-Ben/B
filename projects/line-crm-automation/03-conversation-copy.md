## 0. AI Personality 規範

**角色名稱：** 知育 AI 成長助手

| 要 | 不要 |
|---|---|
| 像一個看過很多公司的顧問在問話 | 像客服機器人在跑罐頭 |
| 短句、留白、一次一個重點 | 一次丟三段說明 |
| 承認不確定（「這部分要看你的實際數據」） | 每句都很篤定 |
| 先給判斷，再談服務 | 每一則都在導購 |
| 全篇最多 3 個 emoji | 每句話配 emoji |
| 專業、冷靜、好奇 | 熱情、可愛、興奮 |

**寫作硬規則**

1. 單則訊息不超過 5 行。
2. 不用驚嘆號，除非引用客戶原話。
3. 不出現「您好」「敬請」「竭誠」這種公文語氣，用「你」。
4. 不出現「AI 可以幫你很多」這種空話，一律講具體工作名稱。
5. 診斷結果出來前，不出現任何服務名稱與價格。

## 2. 題目過場文案

每一題前面加一句短的承接，讓它像對話而不像表單。承接句要根據上一題的答案變化。

### Segment A｜Growth Marketing

| 題號 | 承接句 | 題目 |
|---|---|---|
| GM1 | 了解。行銷這塊我先確認方向。 | 這半年你最想把哪個數字做起來？ |
| GM2 | 收到。 | 目前實際有在跑的有哪些？ |
| GM3 | 好，最後確認一件事。 | 最卡的是哪一件？ |

GM2 承接句變化：
- `revenue` → 「營業額。那我要看的就不只是流量。」
- `leads` → 「名單。這個通常卡在轉換路徑，不是廣告。」
- `unsure` → 「都想是正常的，多數老闆都這樣。我幫你排。」

### Segment B｜AI Transformation

| 題號 | 承接句 | 題目 |
|---|---|---|
| AX1 | 好，我從最基本的開始問。 | 公司現在用 AI 到什麼程度？ |
| AX2 | 記下來了。 | 最想先讓 AI 接手哪一塊？ |
| AX3 | 最後一題。 | 目前最大的卡點是什麼？ |

AX2 承接句變化：
- `L0` / `L1` → 「那你現在的位置，其實比想像中好處理。」
- `L2` → 「員工各自在用，這階段最常見的問題是品質不一致。」
- `L3` / `L4` → 「已經有基礎了，那我們談的層級會不一樣。」

## 3. 分析過場訊息

答完最後一題，立刻用 Reply Token 回這則。這是整個流程最重要的 15 秒。

```
收到。

我正在把你的回答跟我們手上的企業案例對照，大概 15 秒。
```

**如果超過 20 秒仍未完成**，Push 一則：

```
還在算，資料比我想的多一點。再等我 10 秒。
```

## 4. 診斷結果

診斷結果分兩則：Flex 卡片（分數與結構）+ 文字（分析敘述）。

### 4.1 Flex 卡片

見 `flex/diagnostic-result.json`。altText：

```
你的企業診斷結果出來了｜AI Ready Score {{score}}/100
```

### 4.2 文字分析（LLM 生成，200–350 字）

輸出格式固定如下，由 LLM 填入內容：

```
【你的企業診斷結果】

目前狀態
{{current_state}}

最值得優先改善
① {{priority_1}}
② {{priority_2}}
③ {{priority_3}}

我們的觀察
{{insight}}

AI / 數位切入點
{{opportunity}}

建議下一步
Step 1　{{step_1}}
Step 2　{{step_2}}
Step 3　{{step_3}}
```

**`insight` 欄位的寫法規範**

這是整份診斷最有價值的一段，寫法決定使用者會不會覺得「這不是罐頭」。要求 LLM 做的是：**指出表面問題與底層問題的落差**。

好的範例：

> 你選的是廣告成效不穩，但從你同時選了「沒有人專職在做」來看，成效波動比較像是投放頻率與素材更新不規律造成的。這種情況換代理商通常沒用，要先固定產出節奏。

不好的範例（禁止）：

> 你的問題其實很常見，很多企業都會遇到。建議可以導入 AI 來提升效率。

### 4.3 結果後的 CTA 文案

```
這份診斷是根據你剛剛的四個回答生成的。

如果你想聊得更細，我可以把它交給知育顧問，由真人看過之後給你具體建議。不用付費，也不用先決定要不要合作。
```

Buttons（在 Flex footer）：

| Label | Action |
|---|---|
| 交給顧問看 | postback `type=cta&v=consult` |
| 看解決方案 | uri `https://zhiyu.tw/services?utm_source=line&utm_medium=diagnostic` |
| 我先看看 | postback `type=cta&v=later` |

## 5. Lead Qualification 文案

**進入時的說明（只講一次）**

```
好。我問六個問題，顧問看到的時候就知道你的狀況，不用你再講一遍。

大概 40 秒。
```

| 題號 | 文案 | 輸入方式 |
|---|---|---|
| LEAD1 | 怎麼稱呼你？ | 自由文字 |
| LEAD2 | 公司名稱？ | 自由文字 |
| LEAD3 | 主要做哪個產業？ | Quick Reply 8 選 1 + 其他 |
| LEAD4 | 你在公司的角色？ | Quick Reply |
| LEAD5 | 公司規模？ | Quick Reply |
| LEAD6 | 如果要開始，大概什麼時候？ | Quick Reply |
| LEAD7 | 這件事目前的預算範圍？ | Quick Reply |
| LEAD8 | 顧問聯繫你，用 LINE 就好還是留 Email？ | Quick Reply |

**LEAD7 預算題的緩衝句**（這題最容易讓人跳出，一定要加）

```
這題只是讓顧問知道要提什麼方案，不是報價。不確定就選不確定。
```

**LEAD8 選項**

| Label | Value |
|---|---|
| LINE 就好 | `line` |
| 我留 Email | `email` |
| 留手機比較快 | `phone` |

選 `email` 或 `phone` 才追問一次。**不要一開始就要電話。**

### 5.1 完成後

```
收好了。

{{name}}，你的診斷和資料已經送到知育顧問手上。

{{sla_message}}

在那之前，你可以先看這一份：{{resource_url}}
```

`sla_message` 依 Lead Score 變化：

| 等級 | 文案 |
|---|---|
| HOT | 顧問今天之內會親自聯繫你。 |
| WARM | 顧問會在 24 小時內聯繫你。 |
| NURTURE | 顧問會在兩個工作天內看過，需要的話會直接找你。 |

## 8. 隱私聲明全文

放在歡迎訊息第二則，以及 Lead Qualification 開始前，各出現一次簡短版。完整版放 LIFF 或官網連結。

**簡短版（LINE 內）**

```
你提供的資訊會用於這份企業需求診斷與後續聯繫，不會提供給第三方。
你隨時可以要求刪除，直接在這裡輸入「刪除我的資料」。
```

**完整版（官網 `/privacy-line`）需涵蓋**

1. 蒐集項目：LINE User ID、顯示名稱、診斷回答、公司資訊、聯絡方式
2. 蒐集目的：企業需求診斷、服務推薦、業務聯繫
3. 保存期限：最後互動後 24 個月，逾期自動匿名化
4. 第三方處理者：Supabase（資料儲存）、Anthropic（診斷分析，不用於模型訓練）
5. 當事人權利：查詢、更正、刪除、停止利用
6. 聯絡方式：知育行銷有限公司 個資聯絡窗口 Email

**不蒐集的項目：** 身分證字號、財務報表、客戶名單、任何生物特徵資料。診斷不需要這些。
