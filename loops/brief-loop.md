# 迴圈：需求整理

## 目標
把客戶的原始資料，整理成結構化的 brief，存到這一關指定的產出路徑。

原始資料可能是：會議逐字稿、LINE 對話截圖轉的文字、客戶來信、電話後的筆記。
內容會很亂、會跳來跳去、會有一半是閒聊。你的工作是把能用的挑出來。

## 輸入
「本次輸入」底下就是原始資料。空的就停下來問我。

## 每輪要做的事
1. 照 `proposals/briefs/_範本.md` 的欄位整理
2. 客戶講的痛點用原話照抄，放在「這次要解決的問題」，不要改寫成行銷術語
3. 數字全部挑出來放「已知數字」，附上出處（客戶說的 / 後台截圖 / 推估）
4. 原始資料裡沒提到的欄位，寫「未提及」，不要留白也不要編
5. 客戶講過但不知道歸哪的，放「其他」，不要丟掉

## 停止條件（全部符合才算做完）
- [ ] 產出檔存在，路徑就是「這一關要產出的檔案」指定的那一個
- [ ] `_範本.md` 的七個欄位全部都在：客戶在做什麼、這次要解決的問題、已知數字、這次的預算、期限、客戶的禁忌、其他
- [ ] 「這次要解決的問題」是客戶原話，看得出是人講的，不是整理過的書面語
- [ ] 每個數字都標了出處
- [ ] 原始資料裡沒有的欄位寫「未提及」，沒有空白欄位
- [ ] 原始資料裡出現過的數字，一個都沒漏
- [ ] 通過 `anti-style.md` 全部禁用詞和禁用句型檢查

## 不要做的事
- 不要在這一關就開始給建議，這關只做整理
- 不要把客戶的抱怨修飾成中性描述，抱怨本身就是資訊
- 不要推估任何數字
